# 웹핏 블로그 검수 규칙

## 판정 상태

- `통과`: 원고와 근거 자료에서 조건 충족을 확인했다.
- `수정 필요`: 구체적인 문제와 수정 방향을 확인했다.
- `확인 불가`: 필요한 원문, 데이터 또는 사실 근거가 없다.

확인 불가를 통과로 바꾸거나, 수정 필요를 검색 노출 실패로 확대하지 않는다.

## 형태소와 키워드

- 확정 키워드의 핵심 단일 형태소와 의미 있는 결합어를 우선 형태소군으로 둔다.
- 우선 형태소 각각의 횟수, 결합어 횟수와 상위 경쟁 명사를 제시한다.
- 주요 경쟁 명사가 가장 적게 사용된 핵심 형태소보다 많으면 `수정 필요` 후보로 본다.
- 핵심 형태소는 각각 최대 20회이며 가능한 비슷한 수준으로 맞춘다.
- 완전 일치 키워드의 기계적 반복과 부자연스러운 문장을 별도로 확인한다.
- 표면 집계는 형태소 분석기 결과와 같지 않다. 사용한 방식과 한계를 반드시 밝힌다.
- 이 기준을 네이버 알고리즘 공식, 상위노출 조건이나 노출 보장으로 표현하지 않는다.

## EEAT와 사실성

EEAT는 경력 문구의 존재가 아니라 다음 연결로 확인한다.

`확인된 경험 → 무엇을 확인했는지 → 어떻게 판단했는지 → 실제 행동 → 독자가 적용할 기준`

다음을 EXP, 현재 대화, SOUL 또는 실제 검증 자료와 대조한다.

- 고객 유형과 실제 장면
- 처음 보인 문제와 다르게 발견한 문제
- 판단 근거와 실제 행동
- 확인된 결과 또는 현재 상태
- 브랜드 경력, 제작 건수, 기간과 수치
- 고객 발언, 반응과 직접 인용
- 검색 결과, 검색량과 경쟁도 표현

근거가 없으면 삭제를 단정하지 말고 `확인 불가`와 필요한 확인 자료를 적는다. 정확한 발언이 없으면 직접 인용을 간접화법으로 바꾸도록 제안한다. 고객 식별 정보와 민감 정보의 익명화도 확인한다.

## 구조와 발행 준비

- 핵심 주장이 한 문장으로 설명되는가?
- 경험담의 시간순이 아니라 검색자의 질문과 판단 순서인가?
- H2가 정확히 6개이고, FAQ H2 아래 H3가 정확히 3개인가?
- 각 H2 첫 문장이 해당 부분의 답인가?
- 도입부가 검색자의 질문, 빠른 답, 경험 근거와 사례로 압축됐는가?
- 공백 제외 2,000~2,500자를 기본 범위로 검토했는가?
- 일반 정보와 웹핏의 해석이 구분되는가?
- 경험이 장식이 아니라 판단 근거인가?
- 표·목록·FAQ·결론이 같은 내용을 반복하지 않는가?
- 독자가 적용할 기준과 자연스러운 다음 행동이 있는가?
- 본문과 소제목에 금지 형태 `보지`가 없는가?
