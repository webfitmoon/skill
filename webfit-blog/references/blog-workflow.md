# 블로그 설계와 작성

## 키포트 분석

다음을 사용자에게 보여준다.

- 핵심 키워드 1개와 보조 키워드 3~5개
- 검색 계기, 현재 상황과 단계
- 표면 의도와 실제 해결하려는 문제
- 핵심 고민과 피하고 싶은 실패·손실
- 고객이 사용할 법한 속마음 문장
- 내포 질문 5~8개
- 경험이 직접 답할 수 있는 질문
- 현재 경험만으로 단정하면 안 되는 질문
- 경험과 검색 의도가 만나는 한 문장

## 네이버 상위글 5개

브라우저에서 검색 결과 섹션, 제목, 공통 형태소, 스니펫, 가능하면 본문 초반, 글 유형, 공통 질문, 놓치는 지점과 웹핏의 차별 관점을 확인한다. 상위글의 문장·구조·사례·표현 리듬은 모방하지 않는다.

확인하지 않았다면 `최근 검색 결과상`, `현재 상위노출 글을 보면`, `검색량이 높다`, `경쟁도가 낮다`라고 말하지 않는다. 확인했다면 `이번에 확인한 상위글 5개에서는`처럼 범위를 한정한다.

## 제목

`핵심 키워드 또는 검색 상황 + 경험에서 확인한 구체적인 문제·판단`을 기본으로 후보 5개를 만든다. 레거시형, 속마음형과 실패 회피형을 포함한다. 과장된 성과나 확인되지 않은 손실을 약속하지 않는다.

## 소제목

H2는 정확히 6개다.

1. 검색자가 겪는 문제 또는 키워드의 실제 범위
2. 흔한 판단과 웹핏의 판단 차이
3. 경험에서 확인한 판단 근거와 해결 과정
4. 선택지 비교, 적용 기준 또는 주의사항
5. 자주 묻는 질문
6. 결론과 다음 행동

본문 H2는 자연스러운 답변형 문장으로 쓰고 직접 질문형은 FAQ에만 사용한다. 각 H2의 첫 문장은 답이어야 한다. H2 아래 전개는 `핵심 답 → 이유·판단 기준 → 실제 경험 → 독자의 적용 기준`이다.

## 원고

- 기본 분량: 공백 제외 2,000~2,500자
- 모바일 가독성을 위해 문단은 주로 1~3문장
- 도입부: 검색자의 질문 → 빠른 답 → 확인된 웹핏 경험 근거 → 이번 사례
- FAQ H2 아래 H3 질문은 정확히 3개
- 표와 목록은 비교·절차·점검 기준을 더 명확히 할 때만 사용
- CTA는 독자의 현재 단계와 자연스럽게 이어질 때만 사용
- 동일한 경험과 결론을 도입부·본문·결론에서 반복하지 않는다.
- 본문과 소제목에는 `보지`라는 단어를 쓰지 않고 문맥에 맞는 다른 표현을 사용한다.

## 사실과 브랜드

현재 경험과 실제로 읽어 확인한 SOUL 문서에서 확인된 사실만 브랜드 엔티티와 EEAT 근거로 쓴다. 고객 발언은 정확한 문장이 있을 때만 직접 인용한다. 고객 반응, 성과, 기간, 수치와 제작 이력은 확인 없이 만들지 않는다. 웹핏의 전문성은 경력 나열보다 `무엇을 보고 → 어떻게 판단하고 → 무엇을 했는지`로 보여준다.
