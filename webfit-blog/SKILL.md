# 웹핏 경험 기반 블로그 글쓰기

## 목적

확인된 경험에서 웹핏의 판단을 보존하고, 별도로 분석한 검색자의 질문과 결합해 네이버 블로그 원고를 만든다. 경험을 시간순 에세이로 옮기지 않는다.

## 작업공간 준비

현재 위치 또는 상위 폴더에서 `웹핏_경험기반_통합콘텐츠_GPT_지침.md`와 `경험_자산/`이 함께 있는 프로젝트 루트를 찾는다. 작업 전 통합 지침을 처음부터 끝까지 읽고, 지정된 EXP 파일 본문도 실제로 읽는다. 파일명이나 README 요약만으로 경험을 판단하지 않는다. 루트를 찾지 못하면 임의의 경험이나 프로젝트 구조를 만들지 말고 사용자에게 프로젝트 폴더를 요청한다.

## 작업 순서

사용자가 이미 확정한 단계는 반복하지 않는다. 미확정 단계는 다음 순서로 진행한다.

1. 사용할 `EXP-###`의 사실, 장면, 판단 근거, 행동과 결과를 점검한다.
2. 기존 발행 글과 키워드 중복을 확인하고 핵심 키워드와 보조 키워드 후보를 정한다.
3. 키포트 분석을 사용자에게 보여주고 수정·확정받는다.
4. 브라우저로 네이버 상위글 5개를 확인한다.
5. 제목 후보 5개를 만들고 최종 제목을 확정한다.
6. 고객 질문과 판단 순서로 H2 구조를 설계하고 확정한다.
7. 사용자의 원고 작성 승인을 받은 뒤 초안을 쓴다.
8. 사실성, 경험 밀도, 형태소 빈도, 반복과 분량을 검수한다.
9. 사용자가 요청한 경우에만 파일 저장·Drive 업로드·게시를 수행한다.

분석과 작성 전에 [references/blog-workflow.md](references/blog-workflow.md)를 읽는다. 최종 검수에는 [references/blog-quality-gate.md](references/blog-quality-gate.md)를 읽는다.

## 두 축

- 경험 축: 실제 장면 → 표면 문제 → 다르게 발견한 문제 → 판단 근거 → 행동 → 확인된 결과 → 고유한 판단
- 검색 축: 핵심 키워드 → 검색 배경과 단계 → 고민과 실패 회피 → 내포 질문
- 통합: 검색자의 질문에 먼저 답하고 실제 경험을 근거로 사용하며 독자의 적용 기준으로 닫는다.

한 축을 다른 축에 끼워 맞추지 않는다.

## 승인 경계

- 키워드가 정해지지 않은 채 원고를 쓰지 않는다.
- 키포트 분석과 제목·소제목을 사용자에게 확인받기 전 전체 원고를 쓰지 않는다.
- 검색 결과를 확인하지 않았다면 미검증이라고 밝힌다.
- 사용자가 지정한 키워드를 임의로 교체하지 않는다.
- 작성 요청은 저장·업로드·게시 권한을 포함하지 않는다.

## 바로 실행하는 요청

- `$webfit-blog EXP-023으로 블로그 글쓰기 시작해줘.`
- `$webfit-blog 이 경험의 키워드와 키포트 분석부터 진행해줘.`
