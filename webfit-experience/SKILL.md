# 웹핏 경험 원석 쌓기

## 목적

정리되지 않은 실제 경험에서 재사용 가능한 판단 원석을 찾고 `경험_자산/`에 보존한다. 이 스킬의 종료점은 경험 자산 저장이다. 사용자가 명시적으로 요청하지 않으면 블로그나 SNS 글을 만들지 않는다.

## 작업공간 준비

현재 위치 또는 상위 폴더에서 `웹핏_경험기반_통합콘텐츠_GPT_지침.md`와 `경험_자산/`이 함께 있는 프로젝트 루트를 찾는다. 작업 전 통합 지침을 처음부터 끝까지 읽는다. 루트를 찾지 못하면 임의 위치에 자산을 만들지 말고 사용자에게 프로젝트 폴더를 요청한다.

## 시작

사용자가 시작 의사만 표현하면 바로 다음 취지로 묻는다.

> 오늘 콘텐츠로 남길 경험을 정리하지 말고 편하게 이야기해주세요. 고객이 한 말, 작업 중 이상했던 장면, 처음 생각한 문제와 실제로 다르게 발견한 부분이 있으면 함께 말해주세요.

이미 경험을 말했다면 이 문장을 반복하지 말고 분석한다.

## 필수 진행

1. 현재 대화와 제공 자료에서 사실을 먼저 추출한다.
2. 부족한 사실만 한 번에 최대 3개 질문한다. 실제 장면, 판단 근거, 실제 행동, 확인된 결과를 우선한다.
3. 다음 다섯 조건을 확인한다: 구체적인 장면, 표면 문제와 실제 원인의 차이, 판단 근거, 실제 행동·제안, 독자가 적용할 기준.
4. 기존 `경험_자산/EXP-*.md` 전체와 중복을 비교한다.
5. 충분한 경험만 새 파일 또는 기존 파일 보완으로 저장하고 같은 작업에서 `경험_자산/README.md`를 갱신한다.

저장하기 전에 [references/asset-rules.md](references/asset-rules.md)를 반드시 읽는다.

## 사실성 경계

- 고객 이름과 식별 정보는 공개 허락이 없으면 익명화한다.
- 정확한 발언이 확인되지 않으면 직접 인용하지 않는다.
- 경험 발생일을 모르면 `확인되지 않음`으로 두고 현재 날짜를 정리일로만 기록한다.
- 결과가 없더라도 판단 과정이 충분하면 저장할 수 있다. 성과는 추정하지 않는다.
- 여러 관점이 섞이면 핵심 관찰과 독자 기준이 다른 원석으로 분리한다.
- 작은 파생 관점은 `사용하지 않은 후속 글감`에 남긴다.

## 완료 보고

저장 또는 보완한 EXP 번호, 파일, 핵심 주장, README 갱신 여부를 먼저 알린다. 부족해서 저장하지 않았다면 필요한 사실만 질문한다.

## 바로 실행하는 요청

- `$webfit-experience 이번 주 경험 원석을 쌓을게.`
- `$webfit-experience 이 경험을 기존 자산과 비교해서 저장해줘.`
